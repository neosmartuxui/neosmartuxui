NeoSmartUI Foundry

Built for humans.
Structured for agents.

NeoSmartUI is the AI-first neo-brutalist UI system. This Foundry is the public proof surface for one canonical architecture: Components → Blocks → Pages → Applications.

v0.2 Core

The Foundry exercises generic Core primitives through one resolved Rivet Light Theme and adapter-owned rendering boundaries. Public-proof maturity remains separately gated on deployed evidence.

Public-proof component: core.button

core.button is rendered through the Web adapter using resolved semantic tokens. Hover compresses into the surface; press seats the control instead of lifting it.

Public-proof component: core.checkbox

The native checkbox remains the semantic control. A 44px token-backed hit target contains the smaller visual box, with checked and indeterminate state remaining distinct after contact feedback ends.

Public-proof component: core.input

The native text input owns editing and selection. It is interactive, not pressable: hover, focus, and pointer contact never translate the field or simulate button compression.

Public-proof component: core.radio

Native radios preserve one-of-many selection and platform keyboard behavior. Contact compresses into the surface while checked state remains explicit across the whole group.

Public-proof component: core.switch

A native checkbox base exposes switch semantics while checked state stays authoritative. Contact compresses the whole track; persistent state moves the thumb from logical inline-start to inline-end as track color resolves.

Public-proof component: core.tabs

Tabs are a composite widget: roving focus, selected panel, and activation mode remain explicit. Selected tabs stay seated in their rail instead of rising above their peers.

Public-proof component: core.textarea

The native multiline textarea preserves line breaks, selection, scrolling, IME, and resize behavior. It is interactive, not pressable: editing and resize contact never borrow button compression.

Public-proof component: core.select

The native single-select owns its option picker and keyboard behavior. Only the collapsed choice trigger receives pressure feedback; NeoSmartUI does not replace the browser/OS option popup.

Implemented component: core.card

The generic Card groups information without inventing activation. Its resting depth is structural and remains unchanged on hover or pointer contact.

Implemented component: core.badge

Badges communicate compact metadata or status without manufacturing activation or a live region. Tone supports the visible text instead of replacing meaning with color.

Implemented component: core.alert

Alerts are stable message surfaces, not implicit live regions. Tone supports explicit written meaning; announcement urgency remains a composition decision.

Implemented component: core.field

Field composes one real control with its label, help, and validation relationships. The container is not a group, action, or live region; semantics stay on the actual control and associated text.

Implemented component: core.breadcrumb

Breadcrumb exposes a real ordered location hierarchy. Ancestor locations stay native links, separators and passive ellipsis are presentation-only, and the current page is non-interactive text with aria-current="page".

Implemented component: core.pagination

Pagination keeps page destinations as native links with 44px tactile targets. The current page is non-interactive text with aria-current="page", unavailable boundaries stay non-operable, and passive ellipsis never becomes a fake control.

Implemented component: core.segmented-control

Segmented Control chooses one peer mode with real buttons and persistent aria-pressed state. It keeps normal Tab, Space, and Enter button behavior; it does not borrow Tabs roving focus or form-value Radio semantics.

Implemented component: core.tooltip

Tooltip keeps supplemental descriptions non-interactive: keyboard focus remains on the described target, Escape dismisses the surface, and reveal never moves the target.

Implemented component: core.combobox

Editable single-selection Combobox keeps query text separate from committed selection. DOM focus stays on the editable control while active suggestions move through aria-activedescendant; only the separate disclosure trigger uses tactile compression.

Implemented component: core.accordion

Accordion discloses related content with real buttons and ordinary document focus. Space and Enter use native button activation; Arrow/Home/End keys are not remapped into Tabs-style roving focus.

Implemented component: core.label

Label uses native <label> association, stays out of the tab order, and keeps disabled presentation separate from control semantics.

Implemented component: core.separator

Separator provides semantic or decorative boundaries without focus, press physics, or artificial depth.

Implemented component: core.progress

Progress uses native reporting semantics for determinate, indeterminate, and complete task state; it never becomes a user-adjustable Slider.

Implemented component: core.spinner

Spinner is a compact visual busy indicator owned by an already-labeled loading context, with static reduced-motion treatment and no invented percentage.

Implemented component: core.button-group

ButtonGroup clusters related real Buttons without turning actions into a selection model or installing roving focus.

Implemented component: core.input-group

InputGroup composes a primary native editing control with generic adornments while the real Input remains the value, keyboard, focus, and validation authority.

Implemented component: core.toggle

Toggle is a real pressed-state Button: persistent aria-pressed selection stays distinct from transient pointer pressure and never becomes Switch or Checkbox semantics.

Implemented component: core.toggle-group

ToggleGroup coordinates labelled Toggle buttons under explicit single- or multiple-selection policy while preserving ordinary document Tab traversal.

Implemented component: core.number-field

NumberField keeps a real numeric input as the value authority. Typed editing remains non-pressable while optional decrement/increment child actions use native step algorithms and tactile pressure.

Implemented component: core.slider

Slider uses native range inputs for scalar and two-thumb range modes. Each thumb keeps native keyboard/value semantics while range ordering is explicit and direct thumb manipulation alone receives pressure feedback.

Implemented component: core.calendar

Calendar exposes one roving calendar grid with ISO date authority. Active-day keyboard movement stays separate from committed single/range selection, while current and unavailable dates remain explicit and machine-readable.

Implemented component: core.date-picker

DatePicker coordinates ISO date entry and a non-modal disclosure around the shipping Calendar primitive. Single/range values remain explicit while Calendar keeps grid navigation and unavailable-date authority.

Implemented component: core.file-upload

FileUpload keeps one real native file input as selected-file and form authority. Drag/drop feeds that same local authority and never implies network upload.

Implemented component: core.multi-select

MultiSelect keeps zero-or-more committed values in one explicit multi-selection listbox. Transient highlight stays separate from selection, and ordinary Tab traversal enters and leaves the component normally.

Implemented component: core.input-otp

InputOTP keeps one real text input as the logical code authority. Native paste and one-time-code autofill remain intact; partial and complete state never auto-submit the form.

Implemented component: core.color-picker

ColorPicker keeps a real native color input as the value and platform-picker authority. The collapsed control uses tactile pressure while the committed opaque sRGB value stays explicit in text.

Implemented component: core.time-picker

TimePicker keeps a real native time input with min/max/step and segmented editing authority. The editable surface never borrows button pressure and no portable popup-open state is invented.

Implemented component: core.dialog

Dialog uses the browser's native modal top layer and focus containment. Escape, explicit close, and programmatic close restore focus to the invoker while AlertDialog semantics remain a separate future contract.

Implemented component: core.alert-dialog

AlertDialog uses the native modal top layer for an important response-required message, requires a prompt description, and focuses the least-destructive response before an irreversible choice.

Implemented component: core.drawer

Drawer is a modal edge-origin overlay with logical placement, native focus containment, deterministic restoration, and optional intentional swipe dismissal that does not steal ordinary content scrolling.

Implemented component: core.popover

Popover uses the platform non-modal top layer with explicit invocation, native light dismiss, ordinary document focus traversal, and logical anchored placement without becoming Dialog, Tooltip, or a menu.

Implemented component: core.hover-card

HoverCard reveals richer read-only preview content from pointer hover or keyboard focus after a controlled delay, without becoming Tooltip, Popover, a menu, or a focus destination.

Implemented component: core.dropdown-menu

DropdownMenu turns one real menu button into a temporary action menu with managed item focus, arrow/Home/End/typeahead navigation, checkable item state, Escape restoration, and ordinary Tab traversal without becoming ContextMenu, Menubar, NavigationMenu, or a value picker.

Implemented component: core.context-menu

ContextMenu enhances one already keyboard-reachable context target with right-click, context-key, and cancellable long-press invocation while preserving ordinary primary activation, visible fallback discovery, managed menu focus, and native document traversal.

Implemented component: core.menubar

Menubar keeps one persistent application-command menu row in ordinary Tab order, uses visual-direction root roving focus, and opens at most one first-level command menu without becoming site navigation, a toolbar, or a searchable command palette.

Implemented component: core.navigation-menu

NavigationMenu preserves native site/application navigation: real destination links stay in ordinary document traversal, separate disclosure buttons reveal one first-level destination list, and aria-current="page" remains authored route state without becoming an application-command menu or router.

Implemented component: core.toast

Toast queues transient status feedback without blocking interaction or stealing focus: one announcement is visible at a time, priority is explicit, optional passive timers pause for hover/focus/document-hidden state, and dismissal never becomes an application command.

Implemented component: core.table

Table preserves native semantic row/column relationships for static or read-only data: real captions, row/column headers, ordinary document focus for composed controls, and no hidden sorting, selection, editing, grid-navigation, virtualization, or business authority.

Implemented component: core.data-grid

DataGrid is an interactive tabular composite: one managed cell enters the page Tab order, directional keys move focus without silently selecting, Space toggles optional single-cell selection, and explicit edit mode hands native text editing to the cell editor without acquiring data-operation authority.

Implemented component: core.item

Item is a structured content row, not a control: leading/media, title, supporting text, metadata, trailing content, and independent actions stay composable while the row itself never acquires selection, navigation, activation, disclosure, editing, or business authority.

Implemented component: core.list

List owns passive semantic collection structure: real unordered/ordered lists preserve native item semantics and authored sequence while composed Item rows and controls keep their own behavior and ordinary document focus order.

Implemented component: core.description-list

DescriptionList preserves native term/description relationships: real dl/dt/dd source order can express shared terms and multiple descriptions without becoming a List, Item row, Table, Grid, form field, or synthetic interactive control.
